## Skills

| Skill | When it is used |
| --- | --- |
| `asset-pipeline` | Create, export, import, rename or license-check art and audio. Use for Blender work, moving models into Unreal, Fab or Poly Haven assets, AI-generated meshes, textures, sounds and asset names. |
| `devlog` | Write or publish a devlog entry about how the game is being built. Use at the end of a work day, after a milestone, or when someone mentions the devlog, progress notes or the Glass Box prize. |
| `harness-contribute` | Improve the team's AI harness itself, such as a skill, subagent, hook, rule or MCP setting. Use when someone wants the agents to behave differently from now on, or reports a repeated mistake an instruction could prevent. |
| `harness-update` | Update the team's AI harness to the latest version. Use when the session status says the harness is out of date, or someone asks to update it. |
| `kickoff` | Run the team's kickoff, from the theme reveal to a chosen game idea, a one-page brief and a work plan. Use when the theme is announced, when someone says the jam is starting or asks what game to make, or wants to pick between game ideas. Any language. |
| `next-task` | Tell a teammate what is pending and what they should or could work on next, from the game's shared task list. Use when someone asks what is pending, what to do now, what they can pick up, what others are doing, or wants to claim, start, finish or add a task. Any language. |
| `perf-check` | Measure frame rate or check assets and Blueprints against the performance budget (60 fps at 1080p). Use when the game feels slow, stutters or drops frames, before a release, or when someone asks whether assets, meshes, textures or Blueprints fit the budget. Any language. |
| `release` | Package a playable build, create a release branch or merge a release into main. Use when someone asks for a build, a test package, a release or a version number. |
| `ship` | Save and share finished work with the team. Use whenever someone says they finished something or wants to upload, commit, push, save to the repo or share changes, in any language, even if they never mention git. |
| `submission-check` | Verify the game is ready to submit to the jam. Use when someone asks whether the entry is ready, what is missing, how to submit, or as the deadline approaches. |
| `trello-sync` | Read or update the team's Trello board (also called the board). Use only when someone asks for it, such as to create or move a card, note something on the board, or update it at the end of the day. Questions about what is pending or what to work on go to next-task. Any language. |
| `ue-build-test` | Compile the Unreal project and run its automation tests, or explain a build or test failure. Use for build errors, failing tests, CI failures, or to confirm that code works. |
| `ue-editor-task` | Do something inside the open Unreal Editor, such as placing actors, adjusting lighting, creating material instances, building levels or inspecting the scene. |
| `ue-feature` | Implement or change gameplay in Unreal C++. Use for new mechanics, classes, components, systems or bug fixes in the game code. |
